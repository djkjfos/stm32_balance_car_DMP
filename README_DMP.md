# MPU6050 DMP FIFO 修正版

这是从 `C:/Users/15902/Desktop/STM_CLion/F1_balance` 复制出的 CLion 工程。控制器、位置环、速度环、直立环、串口设置及自动启动流程沿用原工程；姿态角改由 MPU6050 DMP 输出的四元数计算。原工程没有被修改。

生成和检查期间，此副本的 PID 初始值发生了变化，现保留副本中的值：直立环 P=170、D=4.5，速度环 P=0.56、I=0.022，位置环 P=0.01；原工程当前分别为 85、7.8、1.4、0.007 和 0.0。请根据自己的调参记录确认，使用 DMP 时仍需重新验证。

## 接入方式

- 使用 MPU6050，WHO_AM_I 为 `0x68`，I2C 7 位地址为 `0x68`，总线为 I2C2（PB10/PB11，400 kHz）。地址和 WHO_AM_I 是不同概念。
- 屏幕在 DMP 固件装载期间推进初始化，仍需面板自身的启动和清屏时间。I2C 提速与屏幕提前初始化不能保证解决所有 FAULT，需要按故障编号排查。
- 每次上电会重新向 MPU6050 装载并校验 DMP 固件，配置六轴四元数、陀螺仪校准和 200 Hz FIFO，收到有效四元数后才继续原来的静止校准。启动日志应显示 `DMP init OK`；失败会显示 `DMP init FAIL step=...`，不会开始驱动电机。
- `Core/user/dmp_attitude.c` 负责 DMP 初始化、FIFO、四元数转 X 轴角度、角度对齐和超时判断；`Core/user/dmp_platform.c` 将 DMP 驱动接到 HAL I2C2；`Core/user/mpu6050.c` 保持原控制器的调用接口。
- MPU6050 的 DMP 固件使用 ±2000°/s 陀螺仪量程。读取的原始角速度乘以 8 并限幅到 int16，以兼容原控制器的 131 计数/(°/s) 接口。它不能恢复较大量程带来的分辨率损失，换算值在约 ±250°/s 限幅；静止噪声和 PID 表现可能与原工程不同。
- DMP 和控制循环都设为 200 Hz，两个时钟可能略有差异；偶尔没有新帧时，以当前角速度预测一个控制周期。长时间无新帧、FIFO 数据异常或传输失败时，沿用原控制器 IMU 故障停机流程。
- 为处理两个时钟的细微差异，一次最多读取 3 个 FIFO 包并使用最新一包；积压更多、FIFO 损坏、I2C 失败或无新帧超时仍会停机。本修改能解决由小量帧积压造成的问题，不代表已经确定实车 FAULT 的原因。

## 编译和测试

用 CLion 打开本目录并选择 Debug 配置。Debug 编译采用 `-Os` 以适应 STM32F103 的 64 KB Flash；调试时部分变量可能被优化。已验证的 Debug 固件约占 62 KB Flash，剩余空间较少。

也可以用 Keil 打开 `MDK-ARM/F1_balance_DMP.uvprojx`；该工程已接入四个 DMP 源文件以及 `STM32_HAL`、`MPU6050` 宏，并已使用 ARMCC V5.06 update 5 编译通过。EWARM 工程配置未接入新增 DMP 源文件。

`Test/run_dmp_tests.py` 使用模拟 I2C、DMP 内存和 FIFO 检查驱动；`Test/run_host_tests.py` 使用模拟传感器检查校准、量程换算和故障保护。这些检查不能替代实际硬件验证。

## 首次上车

原工程包含自动启动，先架空车轮或断开电机驱动，并固定车体。确认启动日志、静止校准成功，手动前后倾斜时观察姿态角、角速度的方向和响应是否与原版本一致，再逐步恢复电机并重新调整 PID。DMP 的延迟、安装方向和噪声表现需要实测，不能保证原 PID 参数直接适用。

I2C2 已改为 400 kHz；每个 5 ms 周期仍需读取原始数据和 DMP FIFO，实际周期需要上板测量。400 kHz 要求接线、供电和上拉电阻支持快速模式。如果出现 I2C 读写错误，请检查接线和上拉，不要关闭故障保护。若需回退，在 `Core/Src/i2c.c` 和 `I2C.ioc` 中把 I2C2 速度恢复到 100000，但慢速可能再次造成周期不足。

出现 FAULT 1 时，串口会输出 `IMU DETAIL stage=... dmp=... HAL=... I2CERR=...`；故障锁定后每秒诊断也会重复该信息，或发送 `STAT 0` 加换行查看。`stage=1` 是原始寄存器读取失败，`stage=2` 是 DMP FIFO；stage=2 时 `dmp=1` 为 I2C 失败，`2` 为 FIFO 溢出或四元数异常，`3` 为新帧超时，`4` 为积压过多，`5` 为追帧读取失败，`6` 为四元数或角度异常。I2CERR 为 HAL 错误码，某些 FIFO 复位操作可能更新它，因此要结合 stage 和 dmp 解读。
